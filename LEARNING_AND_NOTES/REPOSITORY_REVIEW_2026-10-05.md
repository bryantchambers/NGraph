## Three workstreams

### 1. Graph-of-graphs and module discovery

Implemented chain: abundance input and sample-centered CLR (`tax_abund_tad`, pseudocount 0.5) → site graphs from Pearson, bicor, Spearman, or MI-ARACNE → site similarity using edge Jaccard and normalized-Laplacian spectral summaries → Taxon/Site heterograph with three relation families → relation-aware VGAE embedding output and global KMeans taxon partition, alongside a separate DiffPool site-assignment and consensus output. See `scripts/01_ngraph_clr_matrices.R`, `scripts/03_ngraph_site_graphs.R`, `scripts/04_ngraph_graph_of_graphs.R`, `scripts/06_ngraph_build_heterograph.R`, `scripts/07_ngraph_train_vgae.py`, `scripts/08_ngraph_train_diffpool.py`, and `scripts/09_ngraph_deep_module_summary.R` (the heterograph feature construction and exported prevalence field are at `06_ngraph_build_heterograph.R:88-99`; VGAE checkpoint selection at `07_ngraph_train_vgae.py:343-351`; DiffPool checkpoint selection at `08_ngraph_train_diffpool.py:271-276`).

The threshold benchmark outputs cover `prev_3`, `prev_5`, and `prev_10` across four methods (12 combinations). The audited VGAE and DiffPool histories for all 12 combinations contain five epochs and are smoke runs, not converged training. In `prev_5`/Pearson, VGAE AUC is 0.6719 (best epoch 1), silhouette is 0.6195, and KMeans assigns 141/133 taxa to two groups. DiffPool consensus assigns 273/274 taxa to M15 and one to M7. These are computational summaries, not biologically validated modules. The permissive `prev_10` Pearson branch has longer histories (VGAE 120 epochs; DiffPool 160); its 1,797-taxon DiffPool output puts all taxa in M18, so that partition is not evidence of useful module resolution. `prev_5`/bicor has mean density 0.7786 versus 0.1676 for Pearson, a material saturation concern.

No sediment-time-warp correction, aligned local age-grid model, or state-transition learning is implemented. In particular, site-specific graphs alone do not demonstrate that sediment compression distortion has been identified or corrected. The training inputs also mix raw feature scales: `numeric_feature_frame` returns unscaled numeric values, with total reads reaching 9,331,334 while CLR values are around 11.5; the DiffPool “Normalize node features globally” code concatenates/masks but does not scale them. Before retraining, choose and document a train-fitted transform by node type and freeze it for validation/test. Do not claim this explains the collapsed partition without a controlled ablation. DiffPool also applies softmax to assignment logits in `scripts/08_ngraph_train_diffpool.py:77-82`, while installed PyG 2.6.1 `dense_diff_pool` applies softmax internally, so both assignment levels are double-normalized; this is confirmed against the [PyG 2.6.1 dense_diff_pool source](https://pytorch-geometric.readthedocs.io/en/2.6.1/_modules/torch_geometric/nn/dense/diff_pool.html). Test the corrected behavior and compare before attributing the one-module result to it. The input QC is not free of technical structure: `prev_5` PC1 correlates with `detected_taxa_tad` at r = -0.7393. There is no bootstrap module stability, label alignment, functional enrichment, or suitable null comparison yet.

A heterograph feature defect also needs correction: `scripts/06_ngraph_build_heterograph.R:95` computes `prevalence_samples` by dividing each taxon’s positive-sample count by `nrow(abund)` (274 taxa), rather than by `ncol(abund)` (214 samples); current exported values confirm the incorrect denominator. Correct it and verify with a fixture whose taxon and sample dimensions differ. Model/evaluation defects to resolve before interpreting scores: `scripts/07_ngraph_train_vgae.py:347` and `scripts/08_ngraph_train_diffpool.py:273` retain `model.state_dict()` without copying tensors, so the supposed best checkpoint may continue changing during later epochs. The VGAE encoder is relation-aware and retains positive/negative association categories as relation labels, but it does not use numeric edge magnitudes; its default VGAE inner-product decoder is relation-agnostic. Thus the model does not learn relation-specific link scores and is not a full KG learner. Its `module_entropy_proxy` is a literal `0.0` placeholder and cannot be interpreted as uncertainty. PyTorch documents that `state_dict()` returns references to parameter tensors, so these best-state assignments are mutable; use a deep copy or serialize immediately ([PyTorch saving/loading guide](https://docs.pytorch.org/tutorials/beginner/saving_loading_models.html)). The core holdout removes only R2 taxon-taxon edges while retaining R2 features, taxon-site and site-site relations and aggregate features; for `prev_5`/Pearson, 6,043 of 9,720 held-out positives also occur in training cores. Evaluation negatives can include training-positive pairs, are resampled by epoch, and the same held-out AUC selects the model. Script 10 splits candidate pairs 80/20 for calibration using embeddings/topology features from the upstream graph; this is not independent held-out-core validation, and its logistic score is not a biological probability. See `scripts/10_ngraph_link_prediction.py:198-230,327-340` for candidate formation and random pair holdout scoring.

### 2. Knowledge graph substrate and schema

`scripts/15_kg_import_site_sample_proxies.R` generates branch-scoped file-backed node, edge, measurement, ontology-term and manifest tables. Audited `abundance_thresholding` counts are 33,164 nodes, 137,013 edges, 32,150 measurements, 274 taxa, 606 samples, four site nodes, four module nodes and ten ontology-term records. `permissive_hybrid_prev10` has 34,689 nodes, 243,387 edges, 32,150 measurements, 1,797 taxa, 606 samples, four sites, six module nodes and ten ontology-term records. Current node and edge IDs are unique, but each branch has 58 dangling `site_has_sample` edges for controls (`ExrNTC`, `ExrPTC`, `LibNTC`, `LibPTC`, `NEGATIVE`) whose Site nodes are absent. Seven Dataset, six OntologyTerm, and two AnalysisRun nodes are orphaned.

The current graph has eight predicates and no core entity nodes, genes, BGCs, pathways, metabolites, or explicit observed-association/prediction relations. `kg_schema` at `scripts/14_ngraph_local_browser.py:1109-1165` is generated as a descriptive inventory/metagraph; it does not enforce domains, ranges, cardinalities, required provenance, or validation constraints. The ten ontology records are not a curated ontology mapping: no RO grounding, OWL/SHACL constraints, or reasoning is present. Namespace/provenance links to ENVO, MIxS, NCBI and PROV can become high-degree path hubs. Measurement units are absent; define explicit known units or mark values dimensionless/unknown rather than inferring them. Nearest-age/depth matches have no tolerance, with maxima of 1,896.98 y BP for XRF age, 430 years for foraminifera age, and 2.5 cm for SST depth. Grouping raw observations into means loses individual observation identity. The GeoB-specific proxy source contains 113 rows keyed to core `GeoB25202`, while metadata uses `GeoB25202_R1`/`GeoB25202_R2`; `scripts/15_kg_import_site_sample_proxies.R:192-224,276-286` uses nearest-sample matching and silently skips every row because of exact core equality. Define and audit an explicit R1/R2 alias policy before joining, and report all dropped rows. `nearest_sample_match` filters the target sample lookup by available coordinates but does not apply the same filter to its source lookup rows before numeric indexing; this is a latent row-alignment defect if a sample lacks a coordinate (the audited biological rows currently had coordinates). The importer reads directly from `Source/ROCS` paths, so the canonical input-copy architecture and provenance paths need reconciliation. The latest `logs/15_kg_import_site_sample_proxies.log` reports the permissive KG totals (34,689 nodes / 243,387 edges), matching that workstream’s manifest and tables; the abundance-thresholding manifest/tables instead report 33,164 / 137,013. These are separate branch-scoped outputs, not a count inconsistency. The live browser on port 10289 is serving `abundance_thresholding`: `/api/health` reports 33,164 nodes and 137,013 edges. The latest importer log instead describes the permissive output workstream; the live browser and that shared log refer to different outputs. Module-edge IDs omit model system in their construction (no collisions in the current artifacts, but a future collision risk).

## Het.io-style metapath search: the next demo

The live KG path endpoint currently performs an undirected breadth-first search and returns one shortest path subject to an edge filter (`scripts/14_ngraph_local_browser.py`, path handler near the KG routes). It does not implement ordered/directed metapaths, path counts, degree-weighted path counts (DWPC), degree-preserving permutation significance, or a KG learning model. It should not be described as equivalent to Het.io graph search. Het.io’s published approach uses typed paths and path statistics including degree weighting and permutation-based significance; source: [GigaScience paper](https://academic.oup.com/gigascience/article/doi/10.1093/gigascience/giad047/7232825).

Build a bounded demonstration on the `prev_5`/Pearson baseline with two biological sites and the entities already present. Start with domain-valid paths `Site → Sample → Taxon`, `Site → Sample → ProxyMeasurement → ProxyVariable`, and `Taxon ← Sample → ProxyMeasurement → ProxyVariable` (the last explicitly traverses `sample_observed_taxon` in reverse). Only add future pathway/function relations after those entities and predicates are imported and validated. Exclude schema, dataset and provenance hubs from biological paths. Offer source/target selection and show each path with its edge predicates and evidence records. Start with path counts and DWPC; add significance only after a degree-preserving null is implemented and checked. Treat a separate relation-prediction task with a clean held-out split as the KG-learning gate. Keep the graph file-backed until the substrate and validation rules are stable.

## Validation limitations and versions

Existing “Method Validated” plot labels indicate successful artifact generation only; they do not establish scientific validity. A successful plot or HTTP 200 is not evidence of method validity. Treat module assignments, edge predictions, path outputs and proxy matches as exploratory until their gates above pass. Ancient DNA damage/authentication, contamination controls, uneven sampling, age uncertainty, proxy resolution and site-specific sediment compression remain interpretive constraints. Do not infer causal drivers, direct ecological interaction, function, or successful correction of compression from the current graph outputs.
